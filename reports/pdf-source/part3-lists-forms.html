Table, filter and search rules

One DataTable component (TanStack Table v9, server mode) serves every list. The identifier comes first, numbers line up, and the filter state always lives in the URL.

Table rules

  • Rows 40 px on desktop (32 px compact option later), 48 px+ on touch.
  • Sticky header; row hover tint; long names truncate with a tooltip, numbers never truncate.
  • Max 1–2 visible row actions; the rest go in the ⋯ menu.
  • Status = badge with colour and icon and word.
  • Sorting shown with an arrow and aria-sort.
  • No bulk selection in v1: nothing here is a batch job except export.
  • 6–9 columns visible; the rest behind "Columns".

Filters

  • Desktop: one toolbar row, filters apply instantly.
  • Phone: search stays visible; "Filters (2)" opens a bottom drawer with Apply and Reset (batch filtering suits slow data).
  • Sales Orders opens on the Open tab, so completed orders never get in the way.
  • Zero results keep the header and filters visible and offer "Clear filters".

When to validate

React Hook Form: mode: "onSubmit", reValidateMode: "onChange". Limit checks are live warnings (cheap numbers). Research: on-blur validation cut errors 22% (Wroblewski); GOV.UK says never validate while typing: the hybrid respects both.

Good error copy

"Enter tons as a number, like 12.450"
"Choose a supplier"
"Enter the vehicle number like GJ03AX4521"

Avoid

"Invalid input", "Error 422", "Oops! Something went wrong", "Please enter a valid value": no blame, no codes, no "please/sorry".

Numbers, dates and complex data

Every number in the app goes through one file, lib/format.ts. Exact values in tables and forms; compact values only on summary tiles; never floating-point arithmetic.

Why a custom compact formatter?

The browser's built-in compact Indian format printed "1.2KCr" for about ₹119 crore in testing. Money must never pass through JavaScript floats either: API strings go straight to Intl.NumberFormat('en-IN') (which formats strings exactly) and arithmetic like tons × rate uses big.js. Dates go to the API as yyyy-MM-dd, never through toISOString() (which shifts IST dates back a day).

Six ways to make complex data easy

Lead with the answer

Detail pages open with 3–5 stat cards; the full record comes after. Lists show 6–9 columns; the rest are one click away.

Say what it means

"You can deliver up to 9.200 t: limited by Shree Ganesh Metals stock" beats three numbers the user must compare.

Surface exceptions loudly

Shortages, negative stock and aged orders always show colour + icon + words; everything normal stays quiet and grey.

Compare, don't just report

Every KPI carries a comparison ("▲ 31.520 t since 01/09"); progress bars show "18.250 of 30.000 t".

Precision where it's copied

Compact numbers never appear in tables, forms or anything a user might copy into an invoice.

Trade words, one vocabulary

Same labels in lists, forms, badges, toasts and errors. Hindi / Gujarati later through one message dictionary.
